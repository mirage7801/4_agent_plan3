# Validation contract — schema 1.0

The generation service may receive only `task.txt` and the public `description`, ports and metadata in `task.json`. Never send `reference.v`, `tb_*.sv`, `constraints.xdc`, or their full logs to a model. The orchestrator stores an immutable candidate in an independent attempt directory and invokes the CLI. The validator reads but never edits it, and does not call a model or manage retries.

`python tools/validate_rtl.py --source <path> --testbench <path> --top <module> --part xczu3eg-sbva484-1-e --clock-period 5.0 --output-dir <path>` produces exactly one result JSON on stdout and the same content in `<actual output_dir>/result.json`. Paths are absolute; `output_dir` may acquire a unique `_run_...` suffix if the requested non-empty directory exists. `--overwrite` explicitly permits replacing that requested run. Exit 0 means all four stages passed, 1 means candidate failure, 2 means environment/parameters/toolchain failure (including a simulator process failure explicitly summarized as `no candidate RTL evidence`). `--synth-on-sim-failure` explicitly runs synthesis after simulation failure; the final result still reports the first failure. Timeouts can be changed with stage-specific `--*-timeout` flags.

Python `from tools.validator_api import validate_rtl` returns the same fields. `schema_version=1.0` keys, stages and error types are frozen by the paired JSON schemas. `commands` gives actual argv and return codes; raw `log_files` retain stdout, stderr, command, cwd and elapsed time, while `summary` is capped at 1000 characters. `passed` requires exit status plus `TEST_PASS` and a successful `synth_design` marker with a nonempty generated netlist and no ERROR. Failures stop at the first stage by default. Errors are classified from tool diagnostics, never source filename.

The private testbench top must be `tb_<top_module>`. The optional XDC next to the testbench is used automatically, or an explicit `--constraints` may be supplied. The requested clock period is substituted only in the staged XDC. Source/testbench are copied byte-for-byte to a private temporary ASCII work directory for Windows Vivado's Tcl/path compatibility; the original candidate is not modified. Logs and netlists live under the unique output directory, and temporary Vivado intermediates are removed after completion. Actual executable paths are recorded in every command. A completed `synth_design` that reports a critical multi-driven/latch/loop warning is rejected as a quality failure despite return code 0; the log and generated netlist remain preserved, not misrepresented as a tool error.

Team two consumes only `stage`, `error_type`, `summary`, selected `warnings` and the relevant snippet of the candidate code through team three. Team three owns attempt history, result inspection, retry policy and final selection; baseline and generated candidates must use this same validator. Summaries may include the original candidate path, a real line/column, and at most two surrounding candidate lines. Temporary `source.v/source.sv` paths are mapped back to the candidate; testbench locations are labeled as validation-environment issues. If no reliable location exists, the summary says `位置未知` and does not invent a line. Simulation classification reads structured `TB_FAIL kind=... case=... cycle=...` first. Plain numeric mismatches are `functional_mismatch`; latency requires explicit timing evidence or a structured kind, and legacy reset wording alone is insufficient without reset input/case evidence. A simulator process failure without `TEST_FAIL` is `unknown_error`; raw logs remain authoritative. `summary` remains capped at 1000 characters and schema version remains 1.0.
